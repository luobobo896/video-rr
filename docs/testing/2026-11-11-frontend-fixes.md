## 4. 本轮反馈问题

### 4.1 中英切换 / 手机英文底栏

- 底部导航英文不再复用桌面长标签，改为 `Home / Browse / Wall / Ranks / Me`，并加 `data-i18n-ignore`，避免 DOM 翻译再次拉长。
- 底部导航改为 5 列等宽网格，单项允许收缩并省略，防止文字重叠。
- ≤599px 顶栏换行：第一行品牌、语言、登录；第二行搜索独占整行。320px 下搜索输入从 0 宽恢复到 236px。
- 静态资源版本提升到 `?v=20261111fix3`，避免浏览器继续使用旧 CSS。

验证：

- 320×700 英文首页：底部 5 个入口均可见，无重叠，页面 `scrollWidth=320`。
- 390×844 英文首页：底部 5 个入口均可见，搜索输入 306px，页面 `scrollWidth=390`。

### 4.2 头像上传慢、上传后要刷新

- 上传前在浏览器用 Canvas 居中裁成方形、最大 512px、WebP 压缩，显著降低上传体积。
- 头像接口支持 `image/png`、`image/jpeg`、`image/webp` 原始二进制；保留原 JSON dataURL 兼容路径。
- 上传中显示「上传中…」并禁用 file input；成功后立即替换头像 `src` 并重新渲染个人中心，不再依赖手动刷新。
- 原始图片允许到 8MB，压缩后服务端上限 1MB。

验证：

- 浏览器构造头像文件并触发 file input change：上传后 `#me-avatar` 立即变为新的 `avatar-<id>-<timestamp>.webp`，图片 `complete=true`，无 Console error。

### 4.3 后台用户管理序号

- 用户管理表首列改为「序号」，账号列不再把 `#id` 塞在账号下方。
- 实测 admin 账号 1-4 依次显示为独立序号列。

## 5. 关于「没有用 Vue」的检查结论

**不是「没用 Vue」本身导致了这些缺陷。** 当前项目是原生 ESM、无构建、零第三方运行时依赖，这个约束本身可以工作；真正的问题是三件事叠加：

1. `public/app.js` 约 2900 行、`admin/app.js` 约 5000 行，路由、状态、渲染、弹层、请求和业务逻辑耦合在一个入口文件里，复制代码后很难发现断链。
2. 没有 TypeScript、ESLint 或 `no-undef` 静态检查，`node --check` 只验证语法，因此 `openOverlay` 这种未定义引用能直接进入运行态。
3. C/B 两端重复实现 `api`、escape、toast、dialog、分页和样式，任何一边修复都可能漏到另一边。

本轮没有引入 Vue 或构建链，原因是项目明确要求原生 ESM、无构建、零依赖；直接迁移会是一次大范围重写，风险高于当前修复。建议下一步按优先级选择：

- 短期：补 ESLint/`no-undef` 和浏览器冒烟测试，至少覆盖提现、上传、登录态、移动端导航。
- 中期：把 `api`、escape、toast、dialog、分页抽成共享原生模块，再按路由拆页面文件。
- 如果明确接受构建链，再考虑 Vue 3 + Vite；迁移前先用现有回归和浏览器截图建立基线。

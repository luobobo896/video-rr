# 游客试看、付费与自动建号

日期：2026-11-11

## 目标

游客无需先注册即可观看 15 秒；到时进入付费墙。支付成功后自动创建账号、自动登录并继续播放。邮件不是唯一登录方式，账号密码规则必须明确且不泄露明文凭据。

## 15 秒试看规则

| 场景 | 规则 |
|---|---|
| 起算 | 首次真正开始播放时起算，不在页面加载或点开详情时起算 |
| 累计 | 只累计正在播放且页面可见的秒数；暂停、切后台、缓冲不消耗 |
| 拖动 | 剩余不足 15 秒时禁止拖到试看范围外，前端钳制并提示 |
| 多标签 | 同一 visitor + 内容共享一份试看额度，不能靠开新标签重置 |
| 复用 | 同一 visitor + 内容 24 小时内只发放一次试看；运营可配置 |
| 到时 | 自动暂停，展示付费墙；记录 `trial_end` 和当前播放位置 |
| 授权 | 试看链接有效期覆盖 15 秒 + 60 秒；服务端记录试看会话，前端截断不是唯一边界 |

## 付费跳转

1. 15 秒到时暂停视频，保存当前集和位置。
2. 打开付费墙，展示会员/单片选项和真实价格。
3. 游客选择商品后进入游客收银台；不要求先注册。
4. 支付成功回调先发放权益，再激活账号并签发一次性登录凭据。
5. 客户端轮询游客订单状态，拿到一次性凭据后自动登录，回到原集原位置继续播放。
6. 支付失败、超时或关闭收银台：保留订单和播放位置，允许重新支付；不重复建号。

## 自动建号流程

采用「待激活账号」：

1. 游客开始收银时创建 `status='pending'` 的用户，生成唯一用户名和随机密码，订单绑定该用户。
2. 支付成功回调将用户置为 `active`，发放会员/单片权益，生成一次性 `claim_token`。
3. 客户端用游客订单 token 轮询，支付成功后一次性兑换 `claim_token`，获得正常用户 session。
4. 支付成功页展示用户名和一次性密码，要求用户立即保存；密码不以明文邮件发送。
5. 24 小时未支付的待激活账号由清理任务禁用或删除；已支付账号不受影响。

## 账号与密码规则

- 用户名：`mh` + 10 位小写字母/数字，唯一；生成冲突时重试。
- 密码：12 位随机字符，排除易混淆字符；使用现有密码哈希存储。
- 明文密码只在支付成功页展示一次，可复制/下载；服务端和日志不保存明文。
- 首次登录后引导改密，但不阻断继续播放；改密走现有邮箱验证码流程（需先绑定邮箱）。
- 邮件可选，仅用于找回/通知；绑定后仍可用用户名 + 密码登录。
- 登录方式约束：
  - 用户名 + 密码：自动建号用户的主登录方式。
  - 邮箱 + 密码 / 邮箱验证码：已绑定邮箱的用户可用。
  - 手机号 + 验证码：后续能力，不在本轮。

## 数据模型（提案）

### users 增补

- `username TEXT UNIQUE`：自动建号用户名；老用户可为空。
- `account_origin TEXT NOT NULL DEFAULT 'email'`：`email` / `guest_checkout`。
- `status` 增加 `pending` 状态；待支付账号不可正常登录。

### guest_checkouts

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `order_id` | 关联订单 |
| `visitor_id` | 游客标识 |
| `token_hash` | 游客订单轮询令牌哈希 |
| `claim_token_hash` | 一次性自动登录凭据哈希 |
| `status` | `pending` / `paid` / `claimed` / `expired` |
| `expires_at` | 游客订单有效期 |
| `created_at` / `updated_at` | 时间 |

`token` 和 `claim_token` 只存哈希；客户端持有原始值。`claim_token` 只能兑换一次。

## API（提案）

- `GET /api/play/:id/:no?trial=1`：允许匿名，返回 15 秒试看会话和签名链接。
- `POST /api/guest/checkout`：`{visitorId, productType, planId?, dramaId?, channel, couponCode?}` → 待激活用户、订单、游客 token。
- `GET /api/guest/orders/:outTradeNo?token=`：游客订单状态；支付成功返回一次性 `claimToken`。
- `POST /api/guest/claim`：`{claimToken}` → 用户 session；单次使用。
- `POST /api/auth/username/password`：`{username,password}` → session。
- `POST /api/me/trial`：记录试看开始/结束和位置（或复用现有 view session）。

## 安全与幂等

- 游客 token 使用 32 字节随机值，哈希入库；轮询和 claim 都校验哈希与订单归属。
- 支付回调幂等：同一订单只激活一次、只发一次权益、只生成一个 claim token。
- 用户名唯一冲突重试上限 5 次；密码和 token 不写日志。
- 试看、游客下单、claim 和用户名登录都要限流。
- 退款撤销权益，但保留账号；账号密码不因退款删除。
- 待激活账号 24 小时清理；清理前确认没有已支付订单。

## 验收

- 游客看满 15 秒后暂停并进入付费墙，不能靠刷新/新标签绕过。
- 游客完成支付后自动登录，回到原位置继续播放。
- 支付成功页只展示一次用户名/密码，可复制；邮件不出现明文密码。
- 用户名 + 密码可再次登录；绑定邮箱后可用邮箱登录。
- 重复支付回调不重复建号/发权益；未支付账号不会变成可登录账号。
- 退款后权益回收，账号仍可登录。

## 待确认

1. 是否接受「支付前创建 pending 账号」；替代方案是 `orders.user_id` 可空、支付成功后再建号，但需要重建订单表。
2. 用户名前缀是否固定 `mh`，还是允许用户支付后自定义一次。
3. 首次登录是否强制改密；建议只引导，不阻断播放。
4. 试看额度是否 24 小时；建议运营可配置，默认 24 小时。

## 非目标

- 本轮不做手机号登录、OAuth、自动账号合并。
- 不做切片级 DRM；试看仍受现有签名方案能力限制。
- 不做游客订单的后台人工合并 UI；先由客服流程处理。

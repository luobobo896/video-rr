# 电影单集正片

日期：2026-11-11

## 背景

电影在 C 端和后台出现多集，原因是导入脚本按 `episodeCount` 或时长把电影切成多个 `episode`。电影应只有一个可播放正片，选集是剧集语义。

## 决策

采用方案 A：保留现有 `dramas` + `episodes` 表，`MOVIE` 固定 1 个 `episode`，不新增 `movie` / `playable_asset` 模型。

## 规则

- 导入：`MOVIE` 强制只生成 1 个分集，标题为「正片」，`free_episodes` 固定为 0。
- 后台：电影已有正片后禁止新增分集；分集页隐藏「新增分集」按钮。
- C 端：详情和播放过滤 `status='merged'` 的旧分集；迁移后只展示 1 个正片。
- 旧链接：请求已合并的电影分集时，播放接口回退到第 1 集。

## 存量迁移

- 将多集电影的 HLS 分片按集顺序合并到第 1 集目录下的 `merged/`。
- 分片使用硬链接复用，跨文件系统时回退复制，不重新转码。
- 第 1 集更新为合并后的 `hls_path`、总时长和标题「正片」。
- 第 2..N 集标记 `status='merged'` 并清空 `hls_path`，保留行以免破坏历史和外键。
- `history` 的集号归一到第 1 集，播放位置按前序分集时长偏移。
- 弹幕按同样偏移合并到第 1 集。
- `content_policies.free_episodes` 归零，避免合并后整部电影变成免费；`trial_seconds` 保留，继续作为试看能力。

## 非目标

- 不新增电影/播放资产表。
- 不重新转码存量电影。
- 不改变订单、权益、退款仍按 `drama_id` 结算的口径。

## 迁移步骤

1. 只读预检：`node scripts/migrate-movie-episodes.mjs`
2. 确认输出中的电影、分集数、总时长和 HLS 完整性。
3. 执行：`node scripts/migrate-movie-episodes.mjs --apply`
4. 检查生成的数据库备份、合并播放列表和 C 端详情页。

## 回滚

- 恢复迁移前的 SQLite 备份。
- 删除对应第 1 集目录下的 `merged/`。
- 原始分集 HLS 目录不删除，恢复数据库后仍可继续使用。

## 验收

- 新导入电影只生成 1 个正片。
- 后台不能给电影新增第 2 集。
- 迁移后的电影详情只显示 1 个正片，播放总时长等于原分集时长之和。
- 迁移前的观看进度和弹幕按时间偏移保留。
- `npm test` 中覆盖合并、进度、弹幕、播放列表和策略归零。

# 运营后台使用说明（2026-11 改版）

面向：运营 / 财务 / 客服。对应代码 `server/api-admin.mjs` 与 `admin/app.js`。

## 1. 登录与账号

- 入口：`https://<域名>/video-admin/`（**必须带尾斜杠**；不带会 301 补斜杠）。
- 后台账号（B 端）与 C 端注册用户是两张表、两个登录入口，互不通用：
  - B 端账号在「系统设置 → 用户管理」；
  - C 端用户在「用户 → C 端用户」。
- 口令策略：**≥8 位，同时含字母与数字，不含用户名，不能是常见弱口令，至少 4 种不同字符**（实现见 `server/api-admin.mjs` 的 `checkAdminPassword`）。
- 首次登录 / 被重置后登录会强制改密；改完请同步更新服务器上的 `storage/admin-initial-passwords.txt`。
- 连续输错会按用户名 + IP 锁 10 分钟（计数存在 Redis 的 `mh:login-fail*`，运维可清）。

### 1.1 用户管理（后台账号增删改 + 分配角色）

「系统设置 → 用户管理」列的是 **B 端后台账号**，不是 C 端用户。每行可「编辑 / 分配角色 / 重置口令 / 停用 / 删除」，表头「＋ 新建用户」。

- 角色决定权限（`roles` + `role_permissions`）：超级管理员 / 内容运营 / 财务 / 客服 / 审核员 / 数据分析，新建时必须至少勾一个。
- 重置口令、停用都会**吊销该账号所有在线会话**（旧 token 立刻 401），不需要等 token 过期。
- 安全阀：最后一个启用中的超级管理员不能被停用、不能被摘掉超管角色、不能被删除；也不能删除当前登录的自己。
- 接口：`POST /admin/api/admins`、`PUT /admin/api/admins/:id`、`POST /admin/api/admins/:id/password`、`DELETE /admin/api/admins/:id`（权限 `system.admin`），异常由 `rbac.mjs` 抛带 `status` 的错误、`api-admin.mjs` 的 `fail()` 映射成 400/404/409。

### 1.2 菜单管理（分组树）

权限回答「谁能做什么」，菜单回答「后台长什么样」，两者独立建模：

- 权限树在 `permissions` 表（含 `system.menu`、`system.menu.write` 节点）。
- 侧栏菜单在 `admin_menus` 表（`group_key / group_label / group_sort / label / route / icon / perm_code / sort / visible / is_system`），首次启动按 `DEFAULT_ADMIN_MENUS` 播种。
- 「系统设置 → 菜单管理」（`#/menus`）以「分组 → 子菜单」树展示；分组可改名/改键/排序，子菜单可新增、编辑、隐藏、删除。`perm_code` 必须是 `permissions` 里已存在的权限码；同分组同路由拒绝重复；`is_system` 的内置菜单只能隐藏不能删。侧栏菜单只显示文字，不显示图标；`icon` 字段仅为历史数据兼容。
- `GET /admin/api/me` 只下发当前账号**有权限**的菜单项，因此换角色后侧栏立即变化；改菜单不需要改代码、也不影响任何角色授权。
- 接口：`GET /admin/api/admin-menus`、`POST`、`PUT/DELETE /admin/api/admin-menus/:id`、`POST /admin/api/admin-menus/reset`（权限 `system.menu` / `system.menu.write`）。
- 分组接口：`PUT /admin/api/admin-menu-groups/:key`。
- C 端成人菜单是独立配置：`#/adult-settings` 维护启用状态与中英文标签；剧集需勾选“成人内容”才会进入成人列表，普通首页、分类、搜索和榜单自动排除。

### 1.3 角色与权限

「系统设置 → 角色管理」（`#/roles`）是独立角色 CRUD 页面：

- 角色表格显示角色名、编码、说明、成员数、权限数和类型；支持新增、编辑、删除和分页。
- 「分配权限」是独立的行内按钮，点击后在弹窗中展示权限树；支持搜索、展开/收起、全选/清空和保存，保存后即时生效。
- 角色编码创建后不可修改；内置角色不可删除；仍分配给后台账号的自定义角色也不能删除。
- 权限树来自 `GET /admin/api/roles/:id/menus`，保存走 `PUT /admin/api/roles/:id/menus`；角色增删改走 `POST/PUT/DELETE /admin/api/roles`。
- 角色成员仍在「用户管理」里分配；敏感权限由接口层二次校验，不能只靠菜单隐藏。

### 1.4 分销配置

- 入口：「交易与财务 → 分销配置」（`#/distribution-config`）。「经营数据」和「分销分析」页右上角也有快捷入口。
- 可配置：分销启停、启用级数、总佣金比例上限、冻结天数、最低结算金额、申请审核方式、归因窗口、逐级佣金规则、提现方式与币种汇率。
- 配置单位：佣金比例按百分比填写，金额按元填写；保存时由前端转换为数据库使用的万分比和分。
- 搜索词监控：C 端每次非空搜索写入 `track_events(type='search')`，「经营数据 → 搜索词 Top 10」按搜索次数排序展示；搜索支持标题、副标题、简介、地区、标签名和内容类型。
- 提现方式：收款信息使用结构化模板（人民币银行卡、国际银行账户、USDT TRC20 或自定义字段），不再手工编辑 JSON；所有收款字段均为必填。
- 响应式：≤900px 时表格转为描述列表，操作按钮独占一行；基础规则表单在 ≤760px 时改为单列。
- 侧栏按权限下发：需要 `growth.distribution.read` 才能查看分销分析，需要 `growth.distribution.write` 才能看到配置入口并保存。超级管理员和财务角色默认具备；内容运营、客服默认不可见。
- 账号看不到入口时，先查「系统设置 → 用户管理」中的角色，不要通过手改 hash 绕过权限。

## 2. 新建剧集（向导）

「内容运营 → 剧集管理 → ＋ 新建剧集」：

1. 只填标题（电影/剧集原名），点「自动搜刮」。
2. 搜刮来源：`data/catalog.json` 内置片库 → Kodi 同源 TMDB → `scrape_cache` → archive.org / `MH_SCRAPE_URL`。
   都查不到时会明确提示「没查到，按草稿填」，**不会编造字段**。
3. 搜刮只补空字段，手动改过的值不会被覆盖；同名词条会提示「站内已有：XXX（#id）」。
4. 底部实时显示「还缺：…」。**字段不全只能存草稿，不能上架**：
   必填 = 标题 / 内容类型 / 付费模式 / 封面 / 年份 / 地区 / 评分。
5. 封面/横幅批量补齐：`内容运营 → 剧集管理` 表头「一键刮削」（`POST /admin/api/artwork/refresh`）。按钮具备防重复、加载态、成功/部分失败反馈；只替换封面单元格，不整页重绘。
   规则：普通补齐优先本地素材/源片；强制重刮优先 TMDB，再回退远程封面。任何失败都保留原图。详见 `docs/SCRAPING-TMDB.md`。
   横幅只补 `banners` 表里有图可用的已上架剧，不会编造无图横幅（`POST /admin/api/banners/autofill` 同理）。

## 3. 付费策略与按集定价

「内容运营 → 付费策略」：

- 一个策略组就是一套完整付费规则（免费 / 会员免费 / 单独收费，配免费集数、试看秒数、单片价、买断或租赁）。组可复用于任意数量剧集。
- 新建剧集时直接选择策略组；「剧集管理」列表的「策略组」列可逐部切换，勾选多部后用列表上方的批量条一次分配。
- 「付费策略」页只维护组和按筛选批量分配，不再要求逐剧填写自定义规则；未分组数量会显示在页面标题旁。
- 修改策略组会实时影响所有已分配剧集；有剧集引用时禁止删除该组。
- 「按集规则」用于组合策略，例如「VIP 免费，但最后 2 集要单独买」：
  - 规则从上到下匹配，命中第一条即生效，未命中的集走整体策略；
  - 起始集必填，结束集留空 = 到最后一集；
  - 规则三种：免费观看 / 需会员 / 需单集购买（会员也要单独买），单集价可单独设；
  - 新增一行默认给「最后两集单独收费」，不会因为忘记改而把整部剧变成会员专享。
- 判定优先级（`server/entitlements.mjs` 的 `resolveAccess`）：
  已购单片 → 按集规则 → 会员覆盖 → 免费集/免费库 → 拒绝。
- 按筛选批量分配支持标题关键词、内容类型和上架状态，先预览影响数量再应用。

## 4. 标签

「内容运营 → 标签管理」：

- 支持一级/二级（最多两级），列表分页，启停开关即时生效（C 端筛选立刻看不到停用标签）。
- 改名、换父级走「编辑」弹层；删除二级标签会先解挂，不会留下孤儿绑定。

## 5. 榜单

「内容运营 → 榜单」：

- 自动榜每天按用户行为重算（服务启动 60 秒后跑一次，之后每 6 小时一次）：
  热播 = 播放 + 完播×2 + 收藏×3 + 成交×5（近 30 天）；飙升 = 近 7 天同比；搜索 = 搜索词命中；口碑 = 评分 + 收藏。
- 人工插入或想固定的条目点「锁定」，重算时原位保留；「刷新此榜 / 立即刷新全部」可手动触发。

## 6. 数据

- 概览（`#/dashboard`）展示平台资产，并有近 7 日播放/观众/新增用户折线、内容类型环图、待处理事项排行和转码队列。
- 收款、订阅、退款在「数据概览 → 经营数据」（`#/analytics`）。
- 匿名访客进入 C 端时自动生成本地访客 ID（`mh-visitor-id`），浏览、曝光、选集、播放、付费墙、登录、收藏、下单与支付事件都会归到同一 `visitor_id`；登录后访客记录关联 `user_id`。
- 埋点明细在「数据概览 → 埋点数据」（`#/events`）：访问开始、页面浏览、内容曝光、详情页浏览、选集点击、开始播放、播放结束/失败、付费墙展示/点击、登录打开/成功、收藏、搜索、分享、分类筛选、榜单浏览、创建订单、支付成功。
- 经营数据的转化漏斗按同一访客逐级去重，只统计完成前序步骤的人；相邻阶段转化率不会超过 100%，图表同时展示播放/访客趋势、关键事件趋势、收入趋势、播放来源和渠道分布。新数据按匿名访客 ID 归因，历史无访客 ID 的事件按 `user_id`/IP 回退，避免升级后漏斗全空。
- 剧集列表的搜索、内容类型、状态、每页数量和分页全部在服务端执行。
- 支付渠道、邮件通道均为列表 + 弹窗编辑；邮件测试可指定收件邮箱并真实发送。
- 验证码邮件模板可在「邮件设置」中修改主题、标题、引导语、页脚和强调色，并实时预览；验证码使用大号等宽字体。
- 「用户 → C 端用户」支持管理员直接改密或发送临时密码邮件；两种操作都会吊销该用户全部旧会话。

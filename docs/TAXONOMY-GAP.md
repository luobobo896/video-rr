## 2. 内容覆盖度（真正的差距）

参考站首屏一页 31 张卡、无限滚动，按此推算在库内容上千部。影巢当前：

| 指标 | 数值 |
| --- | --- |
| 剧集（dramas） | 9 → 批次二导入完成后 21 |
| 分集（episodes，可播） | 12 → 约 46 |
| 频道分布 | 动漫 5 / 纪录片 2 / 电影 1 / 短剧 1 / 电视剧 0 / 综艺 0 |
| 类型命中 | 动画 6、科幻 2、历史 2、喜剧 2、动作 1、冒险 1、医疗 1、奇幻 1、美食 1；其余 11 个类型为 0 |
| 地区命中 | 美国 2、其他 7；英国/韩国/日本/泰国/内地/港台 全 0 |
| 年份命中 | 2011—2020 4、2000—2010 3、90 年代前若干；2022 之后全 0 |

结论：**筛选框架已经 1:1，缺的是把每个格子填满的片源**。参考站是版权采买 + 5000+ 条目，影巢目前用的是 archive.org 的公有领域/CC 授权片，能拿到的数量与地区分布天然受限（英剧/韩剧/日剧/内地剧几乎没有可免费商用的长片源）。

## 3. 本轮已落地的技术改动

- `server/api-public.mjs`
  - 新增 `CATEGORY_CHANNELS` / `CATEGORY_SORTS` / `CATEGORY_REGIONS` / `CATEGORY_GENRES` / `CATEGORY_YEARS` 五组枚举，全部导出，`/api/constants.taxonomy` 一并下发，前端不再硬编码。
  - `GET /api/category` 支持 `type|channel`、`sort`、`region`、`year`、`genre`、`tag`、`page/pageSize`，返回 `facets`（每个选项带 count）+ `active`。
  - 修复频道条件只作用于 facets 而未作用于主查询的缺陷（`type=TV` 曾返回全站 total）。
- `server/rank.mjs` 新增 `HIGHRATE` / `EXPECT` / `QUARTER` / `HIDDEN` / `PLAYLIST` 五种自动榜单策略，全部由播放、收藏、弹幕、评分、上架时间算出，无需人工配。
- `scripts/normalize-taxonomy.mjs`：把 9 个榜单、20 个类型标签、10 个特色标签、剧集分类归一做成幂等脚本，可重复执行。
- `public/app.js`：分类页六排筛选（带计数、可折叠、可清空、状态写进 URL、埋点 `category_filter`）、片单广场页、导航扩到 24 项。
- `public/styles.css`：筛选行横向滚动（移动端不撑破页面）、`min-width:0` 修正 grid 溢出。

## 4. 若要继续贴齐参考站，下一步优先级

1. **播出时间表**：需要 `dramas.release_weekday` / `update_schedule` 字段 + 周视图页面（无真实数据前先做骨架并标注「暂无排期」）。
2. **片单人工编排**：新增 `playlists` / `playlist_items` 表，后台可选片组单，C 端 `#/playlists` 改读它（现在是拿首页楼层顶替）。
3. **内容填充**：按频道补片源——电视剧（公有领域美剧已有 2 部在导入）、综艺（无免费源，需自制或采买）、动漫（Blender 开源动画已用尽，需另行寻找 CC 动画）。
4. **讨论/评论**：参考站每个剧有讨论区，影巢 `comments` 表与后台审核队列已具备，C 端接口尚未开放。

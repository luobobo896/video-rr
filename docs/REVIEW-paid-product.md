# 评审报告：C 端内容付费产品（影巢 / video-rr）

> 评审角色：资深产品经理 + 资深技术经理
> 评审对象：当前已交付系统 + 本轮补充的业务规则（免费 1 集 / 订阅 / 单片付费 / RBAC / 支付宝 + USDT）
> 评审日期：2026-11-10
> 结论：**当前状态 = 可演示、可小范围试用；不可商用上线。** 阻断项 3 个（P0），见第 2 节。

---

## 1. 现状判断（对照代码，不是凭空评）

| 能力 | 现状 | 判定 |
|---|---|---|
| 内容模型 | `dramas(fee_mode: free/vip)` + `episodes.vip` 布尔双写 | ⚠️ 规则会打架，无法表达「第 1 集免费 + 其余订阅 + 单片解锁」 |
| 免费策略 | 无「首集免费」概念，靠人工把 ep1 的 vip 标 0 | ⚠️ 运营易错，且电影只有 1 集时等于没有免费内容 |
| 订阅权益 | `users.is_vip` + `vip_expire_at`，单档位、无权益范围 | ⚠️ 无法表达「A 档看剧集、B 档看剧集+电影」 |
| 单片购买 | 不存在（orders 表只有 sku/amount，无内容归属） | ❌ 缺失 |
| 订单/支付 | `orders(status: pending/paid)` + 后台手动「标记已支付」 | ❌ 无真实渠道、无回调验签、无退款、无对账 |
| 后台权限 | 只有一个 `admins` 表 + 单角色 token | ❌ 无 RBAC、无菜单/按钮/数据权限、无审计 |
| 播放鉴权 | `/api/play` 校验 `episode.vip && !登录` 即拒；切片 URL 永久公开 | ❌ 切片可被直接盗链，订阅等于没锁 |
| 审核 | 弹幕/评论有 pending/approved/rejected | ✅ 基础可用，缺举报/申诉/敏感词 |
| 运营 | Banner/楼层/榜单可配 | ✅ 基础可用，缺价格/活动/优惠券/限免 |
| 播放体验 | HLS 720p/480p、断点续播（历史写库） | ✅ 可用，缺清晰度手选/错误码/DRM |
| 容量 | 实测出口 19 Mbps（单机 ≈22 人 480p） | ❌ 与 1000+ 目标差 45 倍，必须 CDN |

**一句话**：产品骨架在，但**「谁在什么条件下能看什么」这条主链路目前是用布尔字段硬编码的**，一旦接真实支付和 RBAC，现有模型撑不住。

## 2. 核心问题（按严重度）

### P0-1 权益模型缺失，三条业务规则无法同时成立

需求里其实存在**三种互斥/叠加的授权来源**：

1. 免费（首集 / 免费库）
2. 订阅（档位 × 内容池 × 有效期）
3. 单片购买（一次性、永久或限时）

现在的 `dramas.fee_mode + episodes.vip` 只能表达「这集要不要会员」，表达不了：

- 「第 1 集永远免费」是**内容策略**，不是集属性；
- 「订阅后权益范围内可看」需要 **plan → 内容池** 映射；
- 「高价值电影订阅了还要买」需要**单片所有权优先于订阅**的判定顺序。

**没有 Entitlement（权益）实体，后面所有功能（订单、退款、到期、客服、对账）都会补丁摞补丁。**

### P0-2 播放链路没有真正的鉴权，付费等于没锁

`/media/hls/<id>/index.m3u8` 是静态路径，任何人拿到 URL 就能看，且可被第三方站盗链。

- 必须：**签发短时 play_token → nginx `secure_link` 校验 → 切片有效期 5–10 分钟**；
- 否则订阅/单片付费都只是「UI 上的锁」。

### P0-3 支付与订单只有壳，不满足资金安全底线

现状是后台按钮「标记已支付」。真实上线必须补齐：

- 渠道回调**验签 + 幂等 + 乱序处理 + 金额校验**；
- **订单状态机**与超时关单；
- **退款**（含权益回收）；
- **对账**（渠道账单 vs 本地订单，T+1）；
- **补单工具**（支付成功但权益未到账，一线客服可用）。

### P1-1 后台无 RBAC，等于所有操作员都是超管

- 单 admin、密码 `admin123`、无二次确认、无审计；
- 上传接口接受任意二进制并落盘为 `.mp4`，无类型/魔数/大小校验（可被当作文件落地通道）；
- 没有「删除/下架/退款/改价」这类破坏性操作的二次确认与双人复核。

### P1-2 规则表述本身有歧义（需求侧必须拍板）

| 原话 | 歧义 | 影响 |
|---|---|---|
| 「可免费观看 1 集」 | 电影只有 1 集 → 电影是否永远免费？短剧 100 集的首集策略是否不同？ | 定价与转化模型 |
| 「订阅权益范围内其他收费内容」 | 「范围」= 全站？按档位？按分类？ | 无法设计套餐 |
| 「部分电影订阅后仍需付费」 | 是「单片永久」还是「单片 48h 租赁」？ | 订单/退款/权益模型完全不同 |
| USDT 支付 | 用哪条链（TRC20/ERC20）、谁承担汇率与合规主体 | 法务与风控 |

### P1-3 异常路径几乎未定义

支付成功未到账、重复支付、退款后已看内容、订阅到期降级、内容下架对已购用户、回调风暴、跨设备并发播放 —— 这些是上线后 **80% 客服工单**的来源。

## 4. 建议方案（技术落地）

### 4.1 权益模型（核心改造）

```
plans(id, name, price_cny, duration_days, scope)           -- 订阅档位
content_policies(content_id, free_episodes, trial_seconds,
                 access: free|subscription|paid, single_price_cny)  -- 内容策略
purchases(id, user_id, content_id, kind: single|rental,
          expires_at, order_id)                             -- 单片/租赁所有权
entitlements(id, user_id, kind: subscription|single,
             scope, valid_from, valid_to, order_id, status) -- 统一权益视图
orders(id, user_id, amount, currency, status, channel, out_trade_no,
       paid_at, refunded_amount)
order_items(order_id, product_type, product_id, price)
payments(order_id, channel, channel_txn_id UNIQUE, raw, verified)
refunds(id, order_id, amount, reason, operator, status)
```

**判定函数**（唯一入口，全站复用）：

```
resolveAccess(userId, contentId, episodeNo):
  1. purchases 里有该 content 且未过期           → {allow, 'purchase'}
  2. entitlements 有覆盖该 content 的订阅且有效   → {allow, 'subscription'}
  3. episodeNo <= content.free_episodes          → {allow, 'free'}
  4. 未登录/无权益                                → {allow:false, reason, singlePrice, plans}
  5. 试看：返回 trialSeconds（前端按秒截断）
```

接口 `GET /api/access/:contentId/:episodeNo` 返回结构化结果，前端只认这个结果渲染按钮，**不在前端做权限判断**。

### 4.2 播放鉴权链路

```
前端 GET /api/play/:id/:no
  → 服务端 resolveAccess（不通过 → 401/402 + 购买引导）
  → 通过则签发 token = HMAC(uid|contentId|episodeNo|exp, SECRET)
  → 返回 playlist URL: /video/media/hls/<id>/index.m3u8?token=..&exp=..
nginx:
  secure_link $arg_token,$arg_exp;  secure_link_md5 "$secure_link_expires$uri$remote_addr SECRET";
  if ($secure_link = "") { return 403; }
```

要点：token 绑 IP（防转发）或绑设备指纹；有效期 10 分钟，播放器每 5 分钟续签；CDN 侧用同款鉴权（阿里云 URL 鉴权 A/B/C）。

### 4.3 订单状态机

```
created ──支付成功──▶ paid ──发放权益──▶ fulfilled
   │                    │                  │
   │15min 未支付         │退款               │退款
   ▼                    ▼                  ▼
 closed            refunding ──▶ refunded（权益回收/标记）
```

规则：`out_trade_no` 唯一；回调幂等键 = `channel_txn_id`；乱序回调按状态机推进，不回退；`fulfilled` 失败进重试队列（最多 5 次 + 告警）。

### 4.4 RBAC 设计

**角色**：`super_admin` / `content_ops`（内容与上架）/ `finance`（订单、退款、对账）/ `cs`（客服工具）/ `auditor`（只读 + 审核）/ `analyst`（数据）。

**权限点命名**：`<域>.<对象>.<动作>`，例：`content.drama.publish`、`content.episode.upload`、`finance.order.refund`、`ops.banner.edit`、`user.account.ban`。

**三层控制**：
1. 菜单（前端按 permissions 渲染）；
2. 按钮（`v-permission`）；
3. **接口（唯一可信层）**：中间件校验 `role_permissions`，无权限 403 并写审计。

**数据权限**：`scope: all | category | self`（内容运营只动自己创建的剧集）。

**敏感操作**：退款/删除/改价/下架 → 二次确认（输入原因）+ ≥¥500 退款双人复核 + 全量审计；管理员 2FA；密码策略与 90 天轮换。

### 4.5 支付接入要点

**支付宝**：企业账号签约「手机网站支付/当面付」→ RSA2 密钥 → 服务端统一下单 → 异步通知验签（`sign` + `sign_type`）→ 金额与 `out_trade_no` 比对 → 幂等 → 主动查单兜底（`alipay.trade.query`）→ 退款 `alipay.trade.refund`。

**USDT（建议 TRC20）**：
- 每单生成独立收款地址或 memo（避免归集混乱）；
- 定时扫块 TronGrid API，按 `txid` 去重，确认数 ≥19 入账；
- 下单时锁定汇率（15 分钟），过期需重新报价；
- 金额容差（±0.5%）、超付/少付处理规则；
- 归集到冷钱包 + 地址黑名单；
- 明确「虚拟商品不退」并在支付页勾选，法务留存记录。

**对账**：每日 02:00 拉渠道账单 → 三方 diff（渠道/本地订单/权益）→ 自动补单 + 人工工单；差异率 >0.1% 告警。

### 4.6 体验与展示

| 内容状态 | 卡片角标 | 详情页 CTA | 播放行为 |
|---|---|---|---|
| 免费 | 免费 | 立即播放 | 直接播 |
| 订阅可看（未订阅） | 会员 | 开通会员（¥x/月） | 首集可播，其余弹订阅 |
| 单片（未购买） | ¥12 | 购买本片 / 开通会员 | 试看 6 分钟 → 购买弹窗 |
| 已购/已订阅 | 已解锁 | 继续观看 | 直接播 |

统一规则：**点击任何被锁内容 → 先弹「为什么锁 + 买什么 + 多少钱 + 退款政策」**，避免「点了没反应」。

## 5. 上线前验收清单

**产品**
- [ ] 三态（免费/订阅/单片）在列表、详情、播放页表现一致
- [ ] 首集免费对剧集/电影/短剧均有明确定义
- [ ] 订阅档位与内容池映射表经运营确认
- [ ] 到期前提醒、到期降级、续费流程可走通
- [ ] 退款入口、退款政策文案、客服入口可见

**技术**
- [ ] `resolveAccess` 12 种组合矩阵单测通过
- [ ] 无 token / 过期 token / 换 IP 访问切片 → 403
- [ ] 支付回调重放 10 次只发一次权益
- [ ] 支付成功但回调丢失 → 主动查单 5 分钟内补发
- [ ] 退款后权益回收、已看内容策略符合法务意见
- [ ] 1000 并发（目标地区）压测：错误率 <0.1%，首片 <2s
- [ ] CDN 命中率 ≥90%，回源带宽低于出口 60%
- [ ] 数据库每日备份 + 恢复演练成功

**权限与安全**
- [ ] 6 个角色权限矩阵经业务确认
- [ ] 越权测试：内容运营调退款接口 → 403 且审计留痕
- [ ] 敏感操作二次确认 + 大额双人复核
- [ ] 管理员 2FA、密码策略、会话超时
- [ ] 上传接口校验魔数/类型/大小，非视频拒绝
- [ ] 审计日志不可删、保留 180 天、可按人/单据检索

**支付与资金**
- [ ] 支付宝沙箱 + 小额真单各 1 笔成功
- [ ] USDT 小额真链 1 笔，确认数逻辑正确
- [ ] 退款（全额/部分）到账且权益回收
- [ ] 对账任务跑通，连续 3 天差异 0
- [ ] 风控规则命中示例可复现（同 IP 5 单/10 分钟）

**运营与合规**
- [ ] 内容版权授权链存档（每部剧）
- [ ] ICP 备案、经营许可、支付商户资质齐全
- [ ] 用户协议/隐私政策/退款政策上线
- [ ] 价格与活动配置无需发版即可生效
- [ ] 值班表 + 故障预案（支付不可用降级、CDN 切换）

## 6. 不建议现在做（避免过度设计）

1. DRM（Widevine）——先用短时 token + 并发设备限制，成本收益不划算。
2. 自动续费代扣——需要额外签约与合规，先做手动续费。
3. 自建推荐/AB 平台——先用运营位 + 简单规则。
4. 微服务拆分——当前量级单机 + 模块化足够，拆了只会增加故障面。
5. 加密货币多链支持——先 TRC20 一条，跑通再扩。

## 8. 需要业务方立刻拍板的 5 个问题

1. **订阅档位**：几档？每档覆盖哪些分类（剧集/电影/短剧）？价格与周期？
2. **电影免费策略**：电影是否也给「前 6 分钟试看」？还是完全无免费？
3. **单片形态**：永久买断还是 48h 租赁？是否允许订阅用户折扣购买？
4. **退款政策**：虚拟内容是否支持退款？条件（未观看/24h 内）？USDT 是否明确不退？
5. **USDT 合规主体**：由哪家公司收款、是否做 KYC、汇率与税务如何处理？

> 这 5 个不定，P0 里的权益、订单、退款、支付四条链路都无法最终定稿。

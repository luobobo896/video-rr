# 容量与带宽实测（1000–5000 人点播）

> 结论：**Node 只做 API/鉴权/后台，够用**；点播的并发上限由**出口带宽 + 存储/CDN**决定。
> 本机实测出口只有 ≈19 Mbps，**单机最多约 22 人 480p / 8 人 720p**。要做到 1000–5000 人，必须上 CDN（或换 ≥1 Gbps 专线）。

## 一、这台 HK 机器的真实能力（2026-11-10 实测）

| 项目 | 实测值 | 说明 |
|---|---|---|
| 出口带宽（下行） | **≈19.0 Mbps（2.27 MB/s）** | 8 路并行 Cloudflare 合计 2.27 MB/s，单连接 0.28 MB/s |
| 出口带宽（上行） | **≈19.0 Mbps** | 单连接 2.37 MB/s、4 路并行合计 2.27 MB/s，上下对称 |
| 到大陆延迟 | 2.0–2.6 ms | baidu / 阿里云镜像 / Cloudflare 均 ~2 ms（链路很好） |
| 磁盘顺序读 | ≈278 MB/s | nginx sendfile + page cache |
| CPU / 内存 | 8 核 / 7.8 G，负载 0.1 | 转码与播放共用，需限制转码并发 |
| 软件并发（loopback） | **1000 连接：11116 请求 / 1146 Mbps / 0 错误**；3000 连接：9988 请求 / 0 错误 | 说明 nginx+磁盘能扛，**不是软件瓶颈** |

> loopback 压测里的 Mbps 是「本机内存/磁盘到本机网卡」，不代表公网出口。公网出口被 19 Mbps 硬限，40 路并行下载合计仍是 2.27 MB/s，说明是**总出口限速**而不是单连接或路由问题。

## 二、并发换算

| 并发人数 | 480p（0.85 Mbps） | 720p（2.2 Mbps） | 1080p（4.5 Mbps） |
|---|---|---|---|
| 100 | 85 Mbps | 220 Mbps | 450 Mbps |
| 1000 | **850 Mbps** | **2.2 Gbps** | 4.5 Gbps |
| 3000 | 2.55 Gbps | 6.6 Gbps | 13.5 Gbps |
| 5000 | **4.25 Gbps** | **11 Gbps** | 22.5 Gbps |

- 本机（19 Mbps）：480p 约 **22 人**，720p 约 **8 人**。
- 1000 人 480p 需要 **45 倍**本机带宽；5000 人 480p 需要 **224 倍**。

## 三、要到 1000–5000，怎么改（推荐顺序）

### 方案 A：对象存储 + CDN（唯一能到 5000 的路线）

```
转码完成 → 切片上传 OSS/COS/R2 → CDN 回源拉取 → 用户就近边缘节点拉流
本机只保留：API + 后台 + 转码（转完即删本地切片）
```

- 源站回源带宽 ≈ 总带宽 × (1 − 命中率)。命中率 95% 时，5000 人 480p 回源仍需 212 Mbps → **本机 19 Mbps 不够**，所以切片必须落在对象存储（不经过本机回源），或换 ≥300 Mbps 的机器。
- 成本粗算（按 ¥0.2/GB、每人每天看 2h）：
  - 1000 人 480p ≈ 21.9 TB/月 ≈ **¥4,400/月**
  - 5000 人 480p ≈ 110 TB/月 ≈ **¥22,000/月**
  - 720p 翻 2.6 倍。
- CDN 侧要做：Referer/签名防盗链（`auth_key` / 阿里云 URL 鉴权 A/B/C）、HLS 切片缓存 1h、playlist 不缓存、回源鉴权头。

### 方案 B：换大带宽机器（不接 CDN）

| 目标 | 需要独享带宽 | 现实性 |
|---|---|---|
| 1000 人 480p | ≥1 Gbps | HK/新加坡 1Gbps 独服约 $200–500/月，可做 |
| 3000 人 480p | ≥3 Gbps | 少见，通常要 CDN |
| 5000 人 480p | ≥5 Gbps | 基本只能靠 CDN |

### 方案 C：降码率 + 小并发

480p 再压到 400kbps（AV1/H.265）能把 1000 人压到 400 Mbps，但仍超本机 19 Mbps 20 倍；只适合 <50 人的内部使用。

## 四、软件侧还能做（已做 / 可做）

已做：
- nginx 直接吐切片（sendfile + aio + open_file_cache），Node 不碰视频字节
- `worker_connections 65535`、`worker_rlimit_nofile 100000`
- HLS 多码率（720p/480p）+ master 自适应
- 切片 4s、独立分片（`independent_segments`），CDN 易缓存

可做（按需）：
1. **Node cluster**（8 核）跑 API——当前 API 负载极低（首页 JSON 几 KB），单进程足够；上 5000 人也不到 50 QPS。
2. **HTTP/2**（`listen 443 ssl http2;`）——CDN 之后意义不大，直连时能减少连接开销。
3. 转码与播放隔离（转码限 2 并发，`CPUWeight` 已设 80），避免转码抢占带宽。
4. 播放鉴权：VIP 集用短期签名 URL（`?sign=&exp=`），nginx `secure_link` 校验，防盗链。

## 五、一句话回答

- **Node 够吗？** 够。点播是「静态切片 + 少量 API」，Node 只处理 API，视频字节由 nginx/CDN 出。
- **这台机器能扛 1000–5000 吗？** 不能，出口只有 19 Mbps，实测 1000 人 480p 需要 850 Mbps。
- **要扛怎么办？** 切片上对象存储 + CDN（方案 A），本机只做 API/后台/转码；或换 ≥1 Gbps 独服（只够 1000 人 480p）。
